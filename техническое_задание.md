# Техническое задание: «Планировщик задач»

## 1. Цель проекта

Создать личный веб-планировщик для планирования задач по календарю на день, неделю и месяц. Основная рабочая версия предназначена для компьютера. На телефоне пользователь может открыть страницу, просмотреть имеющийся календарь и удалить задачу.

Приложение состоит из трёх файлов: `index.html`, `styles.css` и `script.js`. Серверная часть, аккаунты, синхронизация и внешние сервисы в эту версию не входят.

## 2. Пользователь и доступ

- Пользователь один: владелец страницы.
- Регистрация, вход и роли не нужны.
- На компьютере доступны создание, просмотр, изменение, перенос и удаление задач, а также импорт и экспорт резервной копии.
- На телефоне доступны просмотр задач и удаление с подтверждением. Сетка и основные сценарии планирования оптимизированы для компьютера.

### Хранение на компьютере и телефоне

Задачи хранятся в локальном хранилище браузера (`localStorage`). Хранилище привязано к конкретному браузеру и устройству. Если открыть страницу на телефоне, там не появятся автоматически данные из браузера компьютера. Для переноса снимка данных между устройствами используются экспорт и импорт JSON-файла. Удаление на телефоне меняет только копию, загруженную в браузер телефона; автоматической синхронизации между устройствами нет.

## 3. Основные сущности и данные задачи

Каждая задача содержит:

| Поле | Тип и правила |
|---|---|
| `id` | Уникальный идентификатор, создаётся приложением. |
| `title` | Название задачи, обязательная строка после удаления пробелов по краям. |
| `date` | Дата задачи в формате ISO `YYYY-MM-DD`. Задача относится к одному календарному дню. |
| `startTime` | Время начала в 24-часовом формате `HH:mm`, допустимый шаг — 15 минут. |
| `endTime` | Время окончания в формате `HH:mm`, допустимый шаг — 15 минут; должно быть позже времени начала. |
| `priority` | Один из уровней: «Низкий», «Обычный», «Высокий», «Срочный». Значение по умолчанию — «Обычный». |
| `note` | Текст заметки. Поле есть у каждой задачи, его можно оставить пустым. |
| `status` | Один из статусов: «Запланировано», «В процессе», «Выполнено», «Отложено», «Перенесено». Для новой задачи значение по умолчанию — «Запланировано». |
| `createdAt` | Дата и время создания записи. |
| `updatedAt` | Дата и время последнего изменения записи. |

Категорий, повторов задач и напоминаний нет.

## 4. Календарь

### Режимы

- **День:** временная сетка одного выбранного дня.
- **Неделя:** семь дней от понедельника до воскресенья.
- **Месяц:** полный календарный месяц с задачами по датам; сетка содержит все недели, необходимые для выбранного месяца.
- При первом открытии приложения показывается неделя, включающая текущую дату.
- Кнопка **«Сегодня»** всегда открывает недельный вид текущей недели.

### Дата и время

- Неделя начинается в понедельник.
- Время отображается в 24-часовом формате.
- Даты интерфейса отображаются в формате `ДД.ММ.ГГГГ`; подписи дней и месяцев — на русском языке.
- Интервал временной сетки — 60 минут.
- Сетка дня и недели показывает планировочный диапазон с 08:00 до 21:00 включительно по границам; отображаются 13 часовых интервалов от 08:00–09:00 до 20:00–21:00.
- Время начала выбирается с 08:00 до 20:45, время окончания — с 08:15 до 21:00, с шагом 15 минут. Часовые строки календаря остаются часовыми, тонкие направляющие показывают меньшие интервалы.
- Минимальная длительность задачи — 15 минут. Это позволяет запланировать короткий звонок, например, с 10:15 до 10:30. Отдельная категория или тип задачи «Звонок» не добавляются.
- Задача может занимать часть часа или несколько часов. Её блок располагается по фактическому времени внутри часовых строк: верхний отступ отсчитывается от 08:00, высота соответствует длительности; при 60 px на час одна минута равна одному пикселю.
- В месячном режиме в ячейке дня показываются названия задач с временем. Если места недостаточно, показываются первые по времени задачи и индикатор количества остальных. При выборе дня пользователь может перейти к его дневному расписанию.
- Сетка визуально выделяет текущий день и выбранную дату.

### Навигация

- Стрелки переходят на предыдущую или следующую календарную неделю и открывают недельный вид независимо от текущего режима.
- Кнопка «Сегодня» открывает неделю, содержащую текущую дату.
- Переключатели режимов «День», «Неделя», «Месяц».
- Заголовок показывает выбранную дату или диапазон дат.
- Выбор даты из календарной сетки открывает выбранный день; доступен переход к соответствующей неделе и месяцу.

## 5. Создание и изменение задач

### Создание

- На компьютере задачу можно создать кнопкой «Добавить задачу» или нажатием на свободный интервал сетки.
- Если задача создаётся нажатием на сетку, дата и ближайшее время этого интервала подставляются в форму. Для почасовой строки началом по умолчанию служит её начало; если оно уже прошло в текущем дне, использовать ближайшее будущее время с шагом 15 минут в диапазоне 08:00–20:45.
- В форме доступны название, дата, время начала, время окончания, приоритет, статус и заметка.
- По умолчанию статус — «Запланировано», приоритет — «Обычный».
- По умолчанию продолжительность новой задачи — 60 минут, если это помещается в диапазон 08:00–21:00. Пользователь может изменить начало и окончание независимо.
- Сохранение выполняется кнопкой «Сохранить»; отмена закрывает форму без сохранения.

### Просмотр и изменение

- Нажатие на блок задачи открывает её подробности.
- Из подробностей можно изменить любое поле, кроме идентификатора и времени создания.
- Изменения сохраняются только после явного нажатия «Сохранить».
- При успешном изменении обновляется `updatedAt` и перерисовываются календарные представления.

### Перенос

- На компьютере задачу можно перенести перетаскиванием в другой свободный интервал календаря или изменением даты и времени в форме редактирования.
- Перетаскивание карточки на колонку другого дня переносит её на этот день; вертикальное положение задаёт начало, округлённое к ближайшему интервалу 15 минут. Длительность сохраняется.
- Перенос через сетку ограничен рабочей сеткой 08:00–21:00. Если у задачи длинная длительность, время начала ограничивается так, чтобы окончание не вышло за 21:00.
- При конфликте с другой задачей перенос отклоняется, данные остаются без изменений, пользователь видит причину. Успешный перенос сразу сохраняется и получает новое `updatedAt`.
- После переноса пользователь может уточнить время и дату через форму редактирования.
- Перенос сам по себе не меняет статус. Пользователь вручную выбирает «Перенесено» в форме статуса.
- Если задача не выполнена и пользователь планирует её на следующий день, он меняет дату/время и вручную устанавливает статус «Перенесено».
- На телефоне перенос и редактирование задач недоступны в этой версии.

## 6. Валидация и пересечения задач

- Название обязательно; после обрезки пробелов оно должно содержать хотя бы один символ.
- Время начала и окончания должны быть выбраны с шагом 15 минут.
- Время начала не может быть раньше 08:00 или позже 20:45; время окончания не может выходить за 21:00.
- Окончание должно быть позже начала. Задачи через полночь и много-дневные задачи не поддерживаются; для следующего дня создаётся/переносится отдельная задача на эту дату.
- Задачи на одном дне не могут пересекаться по времени. Приложение проверяет интервал `[startTime, endTime)` по дате: окончание одной задачи может совпадать с началом другой.
- При попытке создать, изменить или перенести задачу с пересечением сохранение отклоняется. Пользователь видит сообщение о конфликте и может исправить время.
- Текущая редактируемая задача исключается из проверки конфликта с самой собой.
- В месячном режиме задачи также не должны иметь пересекающиеся интервалы, даже если вид не показывает почасовую сетку.

## 7. Статусы и приоритеты

### Статусы

1. **Запланировано** — новый статус по умолчанию.
2. **В процессе**.
3. **Выполнено**.
4. **Отложено**.
5. **Перенесено** — выбирается пользователем вручную после переноса или по его решению.

Статус не меняется автоматически из-за наступления времени, окончания задачи или изменения даты/времени.

### Приоритеты

1. Низкий.
2. Обычный — значение по умолчанию.
3. Высокий.
4. Срочный.

Приоритет отображается в карточке задачи компактной цветовой меткой и текстом или доступной подписью. Различия должны быть понятны и без восприятия цвета.

## 8. Удаление задач

- На компьютере удаление доступно из подробностей задачи.
- На телефоне удаление доступно из списка/карточки задачи.
- Перед удалением всегда открывается подтверждение с текстом «Удалить задачу?» и кнопками **«Я подтверждаю»** и **«Отмена»**.
- «Я подтверждаю» удаляет задачу и сохраняет результат. «Отмена» закрывает диалог без изменений.
- Удаление не происходит по нажатию на фон диалога или клавише Escape; диалог можно закрыть этими действиями без удаления.

## 9. Сохранение данных и резервная копия

- Все операции создания, изменения, переноса и удаления сразу сохраняют актуальный список в `localStorage`.
- После перезагрузки страницы задачи восстанавливаются из локального хранилища.
- Если сохранение невозможно (например, браузер запретил хранилище или закончилось место), показать понятное сообщение; не сообщать об успешном сохранении.
- В боковой панели под фильтрами размещены действия **«Экспорт JSON»** и **«Импорт JSON»**.
- Экспорт скачивает файл `резервная-копия-планировщика-ГГГГ-ММ-ДД.json` со всеми задачами и датой экспорта. Формат файла: объект `{ "schema": "planner-tasks-backup", "schemaVersion": 1, "exportedAt": "ISO-8601", "tasks": [...] }`.
- Импорт принимает JSON-файлы, созданные приложением. До подтверждения текущие задачи не изменяются.
- Перед импортом проверяются схема и версия файла, дата экспорта, массив задач, уникальность идентификаторов, обязательные поля и типы, допустимые даты, время с шагом 15 минут, диапазон 08:00–21:00, статусы, приоритеты, заметки, временные отметки и отсутствие пересечений.
- При некорректном JSON или данных показать понятную причину ошибки и оставить текущие задачи без изменений.
- Перед заменой открыть подтверждение, которое сообщает, что текущий список будет полностью заменён, и показывает количество импортируемых задач. Кнопки: «Отмена» и «Импортировать и заменить». Закрытие диалога клавишей Escape или нажатием на фон отменяет импорт.
- После подтверждения импорт целиком заменяет текущий список, сохраняет его в `localStorage` и обновляет календарь. Пустой список задач является допустимой резервной копией.
- Синхронизации через сеть и автоматического объединения данных нет.

## 10. Поиск и фильтрация

- Полнотекстовый поиск не входит в первую версию.
- В левой панели, непосредственно под переключателями режимов календаря, размещаются две группы цветных фильтров: «Приоритет» и «Статус». В каждой группе есть «Все» и по кнопке для каждого доступного значения.
- Изначально фильтры сняты и показываются все задачи. Нажатие на значение включает или выключает его; можно выбрать несколько значений в каждой группе. Кнопка «Все» снимает фильтры только в своей группе.
- При выборе нескольких значений одной группы задача подходит, если совпало любое из выбранных значений этой группы. Если одновременно выбраны значения приоритета и статуса, задачи должны соответствовать хотя бы одному выбранному приоритету И хотя бы одному выбранному статусу.
- Фильтры влияют на задачи календаря в текущем режиме и диапазоне: день, неделя или месяц. Они не изменяют и не удаляют данные. При переключении периода и вида выбранные фильтры сохраняются до перезагрузки страницы.
- Активные кнопки фильтров выделяются спокойным цветом соответствующей категории, показывают состояние для вспомогательных технологий через `aria-pressed`, а подпись сохраняет текстовое значение; цвет не является единственным способом обозначения.

## 11. Интерфейс и стиль

- Визуальный стиль: минималистичный, спокойный, строгий и уютный.
- Компьютер — основной размер экрана; календарная сетка должна быть удобной для широкого окна.
- Внизу левой панели под фильтрами размещены компактные действия «Экспорт JSON» и «Импорт JSON» для резервного копирования.
- В качестве ориентира использовать приложенный пользователем пример календаря: постоянная боковая панель с переключателями «День», «Неделя», «Месяц» и отдельная основная область календаря. В боковой панели не добавлять другие периоды.
- Над календарём разместить заголовок недельного диапазона, стрелки предыдущей/следующей недели и кнопку «Сегодня».
- Под режимами календаря в левой панели разместить компактные цветные группы выбора фильтров по приоритету и статусу.
- В недельном и дневном видах расположить дни по колонкам, шкалу времени — слева, задачи — блоками внутри сетки. В недельном виде заголовки колонок показывают день недели и дату; текущий день визуально выделен.
- Часовые строки должны иметь более тонкие направляющие для 15-минутных позиций, чтобы короткие звонки и другие короткие задачи отображались точно. Высота блока задачи соответствует её длительности; внутри показываются время начала и окончания и название, если хватает места.
- На экране шириной до 620 px недельный вид показывает компактный ряд из семи дат и список задач выбранного дня. Нажатие на дату обновляет список в пределах недели.
- В мобильных видах дня и выбранного дня недели показываются карточки только для чтения: время, название, статус, приоритет и заметка. У каждой карточки есть отдельная кнопка «Удалить»; редактирование, создание и перетаскивание на телефоне недоступны.
- Месячная сетка на узком экране подстраивается по ширине окна; нажатие на дату открывает список задач этого дня.
- Для месяца использовать привычную календарную сетку с днями недели сверху и карточками/подписями задач внутри ячеек. При нехватке места показывать число скрытых задач и позволять перейти к выбранному дню.
- Задачи различать мягкими фоновыми оттенками и текстовыми метками приоритета/статуса; цвет не должен быть единственным способом передачи значения. Использовать согласованную бежево-голубую палитру.
- Размер текста переключателей режимов — 15 px на компьютере и 11 px на узком экране; подписи дней недели в дневной/недельной сетке — 11 px; числа дат — 12 px; подписи дней недели в месячном режиме — 9 px; кнопки приоритетов и статусов — 13 px.
- На узком экране страница должна оставаться читаемой и позволять просматривать календарь/задачи и удалять их. Разрешено горизонтально прокручивать недельную сетку или показывать список задач выбранного дня.
- На телефоне не требуется поддерживать создание, редактирование и перенос задач.
- Рекомендуемая палитра:
  - фон страницы `#E8EAEB` (чуть более насыщенный светло-серый);
  - фон календаря и карточек `#FFFCF7`;
  - выделение выбранного дня `#DCEAF0`;
  - голубой акцент `#8FAFBE`;
  - вторичный бежевый `#E7D9C6`;
  - основной текст `#3F4A50`.
- Читаемость текста и доступные контрасты важнее точного совпадения с оттенками палитры.
- Кнопки, поля форм, выбранные даты и статусы имеют видимые состояния фокуса и нажатия.
- Подтверждения, ошибки валидации и ошибки импорта объясняются коротким русским текстом.

## 12. Структура файлов

- `index.html` — семантическая разметка приложения и контейнеры календаря, форм и диалогов.
- `styles.css` — стили, сетки, адаптация узкого экрана и состояния элементов.
- `script.js` — модель данных, рендер календаря, формы и диалоги, проверки, локальное сохранение, экспорт/импорт JSON.

Не добавлять обязательные библиотеки, серверные компоненты, сборщик или сетевые зависимости. Приложение должно открываться как обычная веб-страница в современном браузере. Если при открытии через `file://` браузер ограничивает загрузку/скачивание или работу локального хранилища, это поведение нужно обработать и отобразить понятную подсказку; основным способом запуска считать статический сайт через локальный веб-сервер или хостинг.

## 13. Сценарии использования

### Сценарий A: открыть план недели

1. Пользователь открывает страницу.
2. Приложение загружает задачи из `localStorage`.
3. По умолчанию отображается неделя, содержащая текущую дату.
4. Пользователь видит семь дней, часовые строки и размещённые по времени задачи.

### Сценарий B: добавить задачу в свободный интервал

1. Пользователь выбирает свободную часовую строку и нажимает на неё или использует кнопку добавления.
2. В форме указывает название, дату, начало и окончание с шагом 15 минут; при необходимости добавляет заметку и меняет приоритет. Для короткого звонка можно задать длительность 15 минут.
3. Оставляет статус «Запланировано» или выбирает другой.
4. Нажимает «Сохранить».
5. Приложение проверяет поля и конфликты, сохраняет задачу и показывает её в календаре.

### Сценарий C: изменить задачу

1. Пользователь нажимает задачу в календаре.
2. Меняет название, время, заметку, статус или приоритет.
3. Сохраняет изменения.
4. При конфликте времени приложение показывает причину и не сохраняет конфликтующее изменение.

### Сценарий D: перенести невыполненную задачу

1. Пользователь переносит задачу на свободный интервал следующего дня перетаскиванием или меняет дату и время в форме.
2. Если перенос выполнен в форме, пользователь вручную устанавливает статус «Перенесено».
3. Приложение проверяет пересечения, сохраняет новые дату и время, статус и обновлённое время изменения.

### Сценарий E: отметить выполнение или отложить

1. Пользователь открывает задачу.
2. Вручную выбирает «Выполнено» или «Отложено».
3. Сохраняет изменение; событие остаётся в календаре и отличается своим статусом.

### Сценарий F: посмотреть выбранный день или месяц

1. Пользователь выбирает «День» или «Месяц».
2. Перелистывает недели стрелками или возвращается к текущей неделе кнопкой «Сегодня».
3. Просматривает задачи; из месяца может перейти к расписанию выбранного дня.
4. Кнопка «Сегодня» открывает недельный вид недели, содержащей текущую дату.

### Сценарий G: открыть план на телефоне и удалить задачу

1. Пользователь открывает страницу на телефоне.
2. Страница показывает данные, сохранённые именно в браузере телефона, либо задачи из ранее импортированного файла.
3. Пользователь листает недели стрелками, выбирает день недели или открывает месяц, затем находит задачу в списке выбранного дня.
4. Нажимает удаление и выбирает «Я подтверждаю» либо «Отмена».
5. При подтверждении удаляется задача только из локальной копии на телефоне.

### Сценарий H: перенести копию задач с компьютера на телефон

1. На компьютере пользователь экспортирует JSON-резервную копию.
2. Переносит файл на телефон доступным способом.
3. На странице телефона импортирует этот файл и подтверждает замену текущей локальной копии.
4. Телефон показывает задачи из снимка на момент экспорта. Последующие изменения на компьютере сами на телефоне не появляются.

### Сценарий I: отменить удаление

1. Пользователь выбирает удаление задачи.
2. В диалоге нажимает «Отмена».
3. Диалог закрывается, задача остаётся в календаре и хранилище.

## 14. Критерии готовности

- При открытии страницы отображается текущая неделя, начинающаяся с понедельника.
- Доступны полноценные режимы дня, недели и месяца; стрелки переключают календарь на предыдущую/следующую неделю, а «Сегодня» возвращает текущую неделю.
- Под календарём доступны цветные фильтры всех приоритетов и статусов, в том числе совместное применение с логикой И между группами и ИЛИ внутри одной группы.
- Сетка показывает диапазон 08:00–21:00 часовыми строками, а задачи задаются с точностью до 15 минут и визуально занимают правильное положение и высоту относительно начала сетки 08:00. Задачу-звонок можно запланировать на 15 минут.
- Новая задача получает статус «Запланировано» и приоритет «Обычный».
- У задачи есть обязательное название и поля даты, времени начала/окончания, приоритета, заметки и статуса.
- Приложение не сохраняет задачу с невалидным интервалом или пересечением с другой задачей того же дня; смежные интервалы допускаются.
- Перемещение задачи не меняет статус автоматически.
- Создание, изменение, перенос и удаление сохраняются после перезагрузки страницы.
- Удаление требует явного нажатия «Я подтверждаю»; «Отмена» оставляет запись без изменений.
- JSON экспортируется и импортируется с проверкой формата; импорт заменяет данные только после подтверждения.
- На телефоне можно просматривать недельный список по выбранным дням, дневной список и месячную сетку; страница не выходит за ширину экрана.
- С телефона можно удалить задачу отдельной кнопкой только после явного подтверждения; отмена оставляет данные без изменений.
- Интерфейс и сообщения отображаются на русском языке.

## 15. Зафиксированные ограничения первой версии

- Данные хранятся отдельно в каждом браузере и на каждом устройстве.
- Между устройствами нет автоматической синхронизации; обмен выполняется через экспорт и импорт JSON.
- Нет повторов, напоминаний, категорий и полнотекстового поиска.
- Мобильный интерфейс предназначен для просмотра и удаления; полноценное планирование выполняется на компьютере.
- Задачи не пересекают полночь и не могут занимать несколько дат.
